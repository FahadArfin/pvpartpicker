# Catalog confidence and buying improvements

Owner approved all five improvements, starting with catalog cleanup and price accuracy, while current retailer scraping remains active. This plan implements them together in the existing compact Night Inventory / Soft Slate shell. No scraper schedules, leases, feed adapters, backfill state or current prices are to be rewritten.

1. Catalog cleanup and confidence (root): normalize verified manufacturer aliases in the read projection; preserve original IDs/source titles and exact model/package boundaries. Correct ambiguous variant/quantity labels only from recorded evidence. Use explicit unknown labels otherwise. Add reusable observed-price status with timestamps and latest-source failures; preserve the existing 24-hour freshness policy. Test aliases, packages, stale/future/unknown-stock data and latest-source report selection. Integrate small labels in catalog/detail/deal surfaces.
2. Comparison (comparison task): improve compare page with relevant aligned specs, differences-only filter, source/unknown labels and readable selection/actions. Do not invent missing electrical values. Improve Watch/Compare touch targets in shared controls while retaining compact rows. Test meaningful difference grouping; browser keyboard/mobile QA.
3. Whole-build purchase comparison (buying task): pure build-purchase evaluator selects fresh in-stock USD offers with exact selected package and condition; pack rounding retained. Compare complete single-retailer plans with split-retailer choices, show line breakdown, known shipping and unknown shipping separately, never label unknown landed costs as cheapest delivered. Partial coverage stays incomplete and cannot win. Add one compact expandable builder section; never mutate selections automatically. Tests for packs, shipping, mixed condition, missing prices and alternatives.
4. Saved-build alerts (alerts task): owner-authenticated CRUD, additive DB migration, current saved-build identity and quantities, safe ownership/deletion semantics, persistent crossing/rearm state and deduplicated notifications. Require complete fresh coverage; never treat missing lines as zero or send false alerts from stale/unknown-stock offers. Reuse existing scheduled process-alerts and notification/email transport. Add compact alert controls on saved builds and management view. Private analytics must not enter alert payloads. Tests for ownership, crossings, incomplete coverage, edited/deleted builds, duplicate processing and quantity/package handling.
5. Integration/release (root): full npm test/typecheck/build, independent review, inspect affected production-preview routes in both themes at desktop/mobile, keyboard controls and a reviewable QA record. Preserve user draft/watch state during browser work. Commit/PR/CI/merge, publish exact validated source/artifact to existing Sites project, verify live product/package labels, buying UI and protected alert APIs. Confirm normal scraping remains enabled/running throughout; archival work remains paused.

Rulings: no fuzzy model merge; normalize only clear brand aliases. Shipping is optional per-offer cost already in the schema; show a lower bound and unknown status when any quote is missing. Build alerts follow the saved build's current contents and require account ownership; product/offer IDs and quantity are preserved. All five deliverables remain in scope until validated and published.
Ruling: fresh retailer alternatives remain eligible when the previously chosen offer is stale or out of stock, provided product, pack and condition match; missing selection identities fail closed. Nothing automatically edits the build.
