# Attributed historical backfill

The owner requested a slow import of existing Drop.solar history on October 7, 2026. Use the public retailer-URL lookup followed by the matching product HTML. The chart observations are inert JSON in the Next.js stream; never execute fetched scripts, reconstruct chart pixels, or invent daily points. Public prices are attributed to the exact source product page. No source prose or images are copied.

`scripts/drop-history-worker.mjs` consumes a finite queue in the existing D1 `job_state` table. Seed with `--seed`; scheduled runs resume without reseeding. Every Drop.solar request (including robots, lookup and product HTML) reserves a persisted slot at least 30 seconds apart. Only one leased job may run globally. Expired leases recover after five minutes; observation imports are idempotent. The workflow uses `--continuous`: it keeps processing, waits through pacing/cooldowns in bounded sleeps, refreshes its check-in each minute, and hands off unfinished work immediately before the GitHub-hosted six-hour limit (350-minute work window). Hourly scheduling is a recovery trigger, not a processing window. Completed/paused queues do not chain. Per-listing server errors, timeouts and other failures are recorded once with the product, retailer, timestamp and reason, then processing moves to the next listing without an extra retry delay. Parser/identity conflicts are recorded as unmatched review items. Failed records remain in D1 and appear in the owner's existing failed count and recent-results table; seeding does not erase them. Completed queues make no Drop.solar requests. Robots are checked per active run; any published crawl delay lengthens the interval. A 404 robots response means no published policy. Disallow, authentication refusal, 403, 429 and challenge pages still pause the source for owner review, without bypass or automatic resumption.

Matching requires the same canonical retailer URL (tracking parameters excluded, variant parameters retained), new USD condition and exact normalized title or reviewed standalone EG4 inverter aliases. Multipacks additionally require the entire unchanged listing title and an explicit source count matching the stored package. Parent URLs shared by multiple catalog variants and bundles are review items. Unknown or ambiguous items are recorded as unmatched, not guessed. Existing products from every retailer can be queued, but Drop.solar may not track them. No new product, retailer offer or live observation is created by this importer.

Common HTML entities in retailer titles are normalized for comparison. The explicitly reviewed Current Connected FlexBOSS21 title includes the same 48V model, 12–16kW output and UL references; its exact alias is allowed across the existing mapped product, still requiring the same retailer URL and package. New aliases require review rather than dropping descriptive suffixes indiscriminately.

Imported records preserve original UTC timestamps and use `stock=unknown` and a history source ID. Source IDs hash product identity and the recorded dataset. Existing observations are deduplicated by offer and timestamp; price conflicts stop that item for review. Never update current prices, stock, freshness, notifications or alerts. Sales and recent-drop calculations retain their existing exclusion of imported history. The chart explains that Drop.solar records price changes, not daily checks.

Owner/collector authentication is required for `/api/history-backfill` and `/api/history-import`. Public charts receive attribution through the existing history endpoint. No scraper operation is exposed as a WebMCP shortcut. `--status` reports durable counts and recent review reasons without fetching Drop.solar. Credentials stay in the existing collector secret or ignored environment file. The scheduled workflow can be disabled after completion; an empty queue already does no source work.

Review paused jobs through the authenticated status endpoint and diagnose before resuming. There is intentionally no anonymous resume or source-permission override. Local verification covers inert parsing, identity/package failures, conflicts, idempotence, single leases, request spacing, source refusal and preservation of live offers.

October 8 recovery: the earlier worker stopped permanently on a single source HTTP 500 after checking 168 eligible listings. Startup now migrates only the exact legacy `Drop.solar is unavailable (HTTP 5xx); owner review required` pause. It retains request spacing and uses compare-and-swap protection; an active lease or any refusal/policy pause is untouched. No database migration, data deletion or broad permission override is needed.

A server error or timeout during the initial `/robots.txt` check is a recoverable setup error rather than evidence that any product failed. Its reason and one-minute cooldown persist in D1, the listing remains pending, and the continuous worker retries policy verification. Source policy must be known before fetching product URLs. Per-product errors still record and advance immediately.
