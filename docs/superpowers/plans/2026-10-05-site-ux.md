# Site usability implementation plan

**Goal:** Make PVPartPicker easier to browse, compare, plan and recover, retaining its compact equipment inventory.

**Architecture:** Improve existing components and tokens. Add small tested helpers for catalog URL state, comparison presentation and build planning; keep account writes and price evidence authoritative.

**Tech stack:** React, TypeScript, vinext, Cloudflare D1, existing Radix dialogs and Lucide icons.

**Spec:** User's whole-site audit and 9/10 target. Findings and current-run screenshots are recorded in `site/docs/ui-ux-audit.md`.

- [x] Capture desktop and mobile public journeys; mark authenticated coverage limits.
- [x] Catalog: compact heading/ecosystem disclosure, persistent filter URLs, removable active filters, visible details links and practical empty recovery.
- [x] Shared shell: active navigation, skip link, earlier mobile breakpoint, menu keyboard states, separated toast/comparison dock, cached-catalog recovery.
- [x] Builder: conditional next steps, quantity validation, string inventory limits, draft Undo and reliable draft restoration; automatic purchase-cost pricing by default.
- [x] Compare: sourced, unit-aware rows, category context and differences-only mode.
- [x] Product: concise heading, selected section states and accessible alert dialog.
- [x] Secondary workspaces: accurate account failure/retry, deletion protection, scraper identity/loading/empty states, persistent tier selection and checked price times.
- [x] Run behavioral tests, typecheck, production build, independent review, browser regression and responsive/keyboard checks.
- [ ] Commit/push GitHub; publish the exact validated source to the existing public Site.

**Review focus:** corrupted local drafts; stale fixed retailer offers; missing/estimated specs; back-navigation/filter restoration; 390/768px content and keyboard focus. Never equate selected categories or calculated voltage with installation approval.
